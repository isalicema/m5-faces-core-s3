# M5 Faces UI Design System

版本：1.1.1
生效日期：2026-11-05（Asia/Shanghai）
Owner：Alice
适用范围：M5Stack CoreS3 + Faces Keyboard3 的 Home、Music、Radio、收藏唱片架、Connection，以及今后新增的 Faces 页面；同时约束真实网页预览和设备端 320×240 UI。

这份文档是 Faces UI 的总设计规范。它不是展示稿说明，而是新页面的默认设计契约、工程 Brief 基线和验收清单。精确 token 同步保存在 [`faces-design-tokens.json`](faces-design-tokens.json)。

## 1. 权威顺序

发生冲突时，按以下顺序判断：

1. Owner 最新明确确认的设计决定；对外生效的规则应同步到本规范和对应 token。
2. 本文档与同版本 `ui/faces-design-tokens.json`。
3. 当前页面的 `ui/*-layout.json`、真实网页与设备实现。
4. `HOME-MIGRATION.md`、`MUSIC-PAPER-PREVIEW.md`、`RADIO-PAPER-MIGRATION.md` 等页面迁移记录。
5. `design/m5-faces-ui/` 内的历史原型。

历史原型用于理解来源，不得在数值冲突时覆盖当前规范。新增页面不得只凭某张截图“照着感觉画”。

本文档负责语义、原则、流程和例外说明；同版本 JSON 负责精确数值与机器检查。两者不是可任选其一的两套标准：若同版本内容冲突，应视为规范错误并暂停施工，先同步修正；不得让 Engineering 自行选择较方便的一边。

## 2. 设计性格

Faces 的视觉语言是“暖纸上的小型编辑器械”：

- 暖纸底色，不使用冷白色大底。
- 黑色、粗重、编辑感强的层级；信息少而明确。
- 一屏只有一个主要彩色焦点，使用明快、平面的强调色。
- 图形与文字共同表达功能；装饰不能压过状态和操作。
- 操作按钮边界清楚，图标优先，并始终保留 Keyboard3 快捷键提示。
- 320×240 是真实画布，不是桌面网页缩略图。
- 浏览器预览、设备构建、实机安装和 Owner 验收是不同状态，不互相冒充。

| 低电量 | `#B65D00` |
| 严重低电量 | `#C52F32` |

没有新遥测时显示 `--`，不得用原型百分比、缓存值或猜测值填充。

### 3.4 动态 Music 强调色

Music 播放页的强调色来自当前封面／曲目数据，不固定为黄色。它控制状态胶囊、播放按钮、已选循环按钮和进度条。

- 动态色必须配套可读前景色。
- 使用相对亮度阈值 `0.179`：高于阈值用黑字，否则用白字。
- 无动态色时使用中性回退 `#D7C9B2`，前景固定为 `#111111`；该回退组合显式覆盖通用亮色前景 `#000000` 规则。
- 喜欢状态仍使用 `#EF263F`，不被封面色替换。

## 4. 字体系统

### 4.1 字体家族

| 角色 | 网页 | 设备／生成资源 | 使用范围 |
| --- | --- | --- | --- |
| Display | `Impact`, `Arial Black`, sans-serif | macOS Impact 栅格化资源 | 英文大标题、Home 卡片标题、收藏标题 |
| UI Sans | `-apple-system`, `BlinkMacSystemFont`, `PingFang SC`, `Noto Sans CJK SC`, sans-serif | Faces 12／16（Noto Sans CJK SC Regular 衍生） | 中文标题、正文、动态数据 |
| Mono | `Menlo`, monospace | Menlo Regular／页面所需 alpha glyph | 英文副标题、状态、时间、快捷键 |

不得为新页面引入 Inter、Roboto、Space Grotesk 等另一套产品字体。字体文件不得随意复制进仓库；遵循 `assets/fonts/README.md` 的许可和生成方式。

### 4.2 字号角色

字号均指 320×240 画布中的逻辑像素。

| 角色 | 字体／字重 | 字号／行高 | 例子 |
| --- | --- | --- | --- |
| `display.hero` | Impact | `42 / 36` | Home `MUSIC` |
| `display.card` | Impact | `29 / 29` | Home `RADIO` |
| `display.card.compact` | Impact | `26 / 29` | Home `COMPANION` |
| `display.page` | Impact 900 | `18 / 17` | 收藏 `COLLECTION` |
| `title.primary` | UI Sans 850 | `18 / 19` | Music 歌曲标题 |
| `title.collection` | UI Sans 850 | `15 / 18` | 收藏歌单名 |
| `body.primary` | UI Sans 550–650 | `11 / 14–17` | 歌手、歌词、说明 |
| `meta.standard` | Menlo Regular | `9 / 12` | Radio 动态曲目信息 |
| `meta.compact` | Menlo 700–800 | `7–8 / 9–12` | 状态、计数、时间 |
| `shortcut` | Menlo 800–900 | `8–11 / 1×字号` | `M / R / A / J / SPC` |

规则：

- 动态正文、时间和快捷键在原生画布上不得小于 8px。
- 7px 只允许短状态或英文元数据；不能承载主要操作含义。
- 现有收藏副标 `COLLECTED PLAYLISTS` 的 5.5px 是网页候选中的历史例外，不是可复用 token；设备实现或新页面应使用至少 7px。
- 中文不使用 Impact 或 Menlo；标题最多两行，正文必须有明确裁切策略。
- 字形按可见墨迹边界居中，不能只按字体框居中。设备端避免直接分数缩放 VLW 字体，以免丢笔画。
- Display 字距为 `0–0.035em`；Mono 标签可用 `0.05–0.10em`；中文正文不额外拉宽。

## 5. 画布、网格与安全区

### 5.1 画布

- 固定逻辑画布：`320 × 240`。
- 浏览器内部必须保持 1 CSS px = 1 逻辑像素；外部设备壳可以整体放大。
- 默认水平安全边距：8px。
- 视觉内容和可点击区域必须分别检查，不能以浏览器壳尺寸代替画布尺寸。
- 边框默认 1.5px；分割线默认 1.5–2px。

### 5.2 标准详情页头部

详情页默认使用 39–40px 高的共享头部：

- 左侧返回按钮：29×29px 圆形，1.5px 黑边，内部图标 17px。
- 返回按钮与标题间距：7px。
- 右侧必须预留状态与电池；电池组件最小宽度 43px，靠右至 x=312。
- 状态、电池和标题不得重叠；标题过长时截断，不侵占电池槽。
- 底部分割线使用 `#111111`，必要时可降低至约 60% 不透明度。
- 返回动作同时支持 Q／Esc；网页和设备语义一致。

收藏页面当前结构是标准范例：返回／标题／计数／电池。刷新等带 Keyboard3 快捷键的次级操作进入底部控制栏，不得挤进电池区域，也不得只显示图标而隐藏快捷键关系。

### 5.3 底部控制区

- 新页面控制区默认距底边约 8px；Music 为 y=202、h=30。现有 Collection 的 y=214、h=25 在 240px 画布内只留 1px，是已经进入候选的紧凑页面例外，不得复制成新页面默认值。
- 一项动作对应一个独立按钮；不能用文字串模拟三个按钮。
- 紧凑控制栏使用“图标 + 快捷键”，不写“上一张／播放／下一张”等动作文字。
- 刷新等有明确快捷键的页面操作，优先与同页操作放入底部控制栏；不要为了头部尚有空白就塞入顶部。
- 默认按钮：纸面或 `paper.control` 填充、1.5px 黑边、8px 圆角。
- 主要／选中按钮使用页面强调色，并切换为可读前景色。
- 按下反馈为向下 1px；禁用状态降低透明度，但仍保持结构可辨。

## 6. 圆角、边框、阴影与图层

| 对象 | 标准 |
| --- | --- |
| 功能按钮 | 8px 圆角，1.5px 黑边 |
| 小状态胶囊 | 胶囊圆角或 7px 圆角 |
| 封面／唱片套 | 3px 轻微圆角，不加黑描边 |
| Home 卡片 | 使用已冻结的生成素材和边界，不自行改画 |
| Cover Flow 中央阴影 | 约 `0 5px 12px rgba(0,0,0,.42)` |
| Cover Flow 侧面阴影 | 约 `0 2px 6px rgba(0,0,0,.24)` |

图层规则：

1. 页面纸面／纹理。
2. 装饰色块与背景圆。
3. 内容、封面和动态媒体。
4. 标题、状态和控制。
5. 焦点、临时反馈和系统提示。

装饰背景必须与交互内容分层。尤其不得把背景伪元素放入 `preserve-3d` 的 Cover Flow 场景；否则封面进入负 `translateZ` 时，背景会穿到前方。收藏页的黄色圆固定在 `.shelf-view::before` z=0，完整 `.shelf-flow` 固定在 z=1。

## 7. 图标与艺术资源

- 操作图标使用现有 Phosphor 路径和 `MusicIcons.h` 派生资源；保持 MIT 归属。
- 同一动作跨页面必须复用同一图标：返回、播放、暂停、上一项、下一项、喜欢、循环、刷新。
- 收藏刷新使用 Phosphor `ArrowClockwise` Bold 的单一实心路径，放入 13px 图标框；不得把分离的细描边缩小成近似字母 `C` 的残缺圆弧。
- 不使用 Unicode 箭头或临时文字替代已经存在的产品图标。
- Home 的 Music 唱片、Radio 调谐器和 Companion 小脸使用已选择的源素材，不用图标库重新画。
- Home 卡片素材以 4× 渲染，再下采样到 320×240；不要放大 1× 小图造成锯齿。
- 从整页／整卡成图复用艺术元素时，优先使用无外框的原始图层；若只能复用成图，必须按对象真实轮廓做语义遮罩。圆形唱片不得用矩形裁边消除烘焙外框，否则会把圆周削平。主卡仍只能保留一套权威边框。
- 图片加载失败必须有有限重试和可读占位，不允许加载任意远程 URL。

## 8. 页面模板

### 8.1 Home：一主两辅

- 8px 左右边距，6px 卡片间隙。
- Music 主卡：x=8、y=34、304×92。
- Music 主卡可在共同外框内提供 Now Playing 与 Collection 两个区域；热区边界停留在交互层，不额外绘制垂直分隔线，也不拆成两张卡。
- Collection 区使用“唱片从封套上沿滑出”的对象关系，不再画成普通底栏：唱片视觉直径 104px，封套 116×26px，两者共用 x=252px 的中轴，因此封套在唱片左右各多 6px；封套上沿位于卡内 y=64px，并向右、下外框各避让 2px。
- 当前唱片元素的布局／采样框为 104×92px，坐标原点是元素左上角；圆形遮罩半径 52px、局部圆心 `(52,46)`，因此完整圆周在垂直方向各超出元素 6px，并由主卡可视区自然裁切。这是保留原唱片构图的有意几何，不是把 `(52,46)` 当成 104×104 方框中心。不再做任何矩形右裁；遮罩不改变 x=252px 中轴或主卡外框。
- 封套本身就是 Collection 的可见入口；`P` 键帽必须与 `M / R / A` 使用同一黑色胶囊规范。唱片继续复用选定源素材，不为入口重画另一枚唱片图标。
- Radio：x=8、y=132、149×82。
- Companion：x=163、y=132、149×82。
- 英文固定文案：`MUSIC / MAC REMOTE`、`RADIO / INTERNET`、`COMPANION / STACKCHAN`。
- M／R／A 键帽共享同一底部基线。
- 卡片保持暖纸表面；明亮颜色只出现在右侧圆弧区域，不整卡填色。
- 顶部保留 FACES、S CONNECT 和真实电量。

### 8.2 Music：媒体控制器

- 头部必须同时容纳返回、真实音乐来源、连接状态和电池。
- Collection 等同域入口放在与其内容关系最强的位置；当前规范位置为“喜欢”旁的内容操作行，不占用头部状态槽。同行胶囊按钮必须复用同一组件的尺寸、底色、描边和圆角。
- 封面与元数据为主，装饰不能取代六个操作。
- 六项控制固定为上一首、播放／暂停、下一首、喜欢、单曲循环、列表循环；保留 J／SPC／K／H／C／V。
- 动态封面色覆盖状态、进度和选中按钮；不能写死为黄色。
- 封面保持完整方形，不叠加硬半圆遮挡。
- 保留真实标题、歌手、歌词、进度与时间；不得填演示歌曲。

### 8.3 Radio：设备音频控制器

- 专用纸色 `#F4E3C4`，强调色 `#FF655F`。
- 当前已安装 Radio 使用左上 144×39 的整块返回热区和烘焙标题，是既有实机校准例外；新增详情页不得复制这个不可见返回模式，默认使用第 5.2 节的可见返回图标与共享头部。
- 保留右侧平滑珊瑚圆弧和源调谐器图形；不能放大低清位图制造锯齿。
- 三张电台卡与固件电台集一致；切台同步改变卡片、频道、hero 标题和指针。
- 指针过渡 260ms，`cubic-bezier(.2,.8,.2,1)`；支持 reduced motion。
- `Secret Agent` 等含下行字母的标题必须有足够行盒，禁止纵向裁切。
- 音频状态明确写设备／本地输出，不能让网页模拟冒充真机播放。

### 8.4 收藏：浏览器／选择器

- 使用标准详情页头部与底部图标控制区。
- 头部保留返回、标题、计数与电池；刷新位于底部四键栏，顺序为 `R / J / SPC / K`，始终同时显示图标与快捷键。
- 四键栏的刷新图标为 13px `ArrowClockwise` Bold 实心轮廓；按钮尺寸、纸色表面和 `R` 键帽文字与其余三键共享同一组件规范。
- Cover Flow 当前可见高度约为中央 120px、近侧 96px、远侧 72px；近侧约 35°、远侧约 55°。
- 封面使用 3px 圆角、无黑描边、柔和阴影；封面与标题视觉间距约 9px。
- J／K、两侧点击和横滑只浏览；SPC／中央确认才播放。
- 连续输入必须承接当前运动，反向输入不能先完成旧动画。
- 拖动后的 click 必须抑制，避免误播放。
- 装饰黄色圆永远在完整 Cover Flow 后方。

### 8.5 Companion：原生交互例外

Home 上的 Companion 卡片属于纸面系统，使用薄荷绿圆弧；进入 Companion 后沿用 CoreS3／StackChan 原生黑底小脸交互。当前不把详情页强行改成纸面控制器，也不为“统一”而破坏相机、靠近、休眠和唤醒反馈。

### 8.6 Connection：设置列表

- 使用纸面或既有深色连接中心，但返回、状态、真实网络信息和电量语义必须清楚。
- 列表项边界清晰，触摸区完整；快捷键放在右侧，不与网络名称混排。
- 配网、认证和保存状态必须说真话，不用装饰性 CONNECT 点代替实际连接状态。

## 9. 交互、动效与状态

### 9.1 动效原则

- 动效表达对象关系，不为热闹而动。
- 页面切换和数据刷新不得闪出白底；新场景未准备好时保留上一完整帧。
- 封面、指针、进度等运动应连续；不要在动画中重新解码大图或整页重绘。
- 支持 `prefers-reduced-motion`；设备端提供即时落位或低成本近似。
- 浏览器流畅不等于 CoreS3 流畅，设备帧率和内存需单独验证。

### 9.2 必备状态

每个联网或可操作页面至少设计：

- 默认／已连接。
- 加载中。
- 空结果。
- 网络或登录失败。
- 陈旧数据。
- 动作发送中。
- 动作结果未知。
- 禁用。
- 返回／重试路径。

读取失败不能冒充空结果，动作已发送不能冒充设备已经执行，浏览不能自动触发播放。

## 10. 触摸、键盘与可读性

- 可见按钮不足 32px 时，扩展透明触摸区；触摸区之间不得重叠。
- 主要操作尽量达到 32×32px；横向长按钮可降低高度至 25–30px，但需保持明确边界。
- 卡片使用完整可见范围作为触摸范围。
- 所有触摸动作必须有 Keyboard3 对应或明确说明例外。
- Q／Esc 默认返回；S 默认进入连接中心；页面专属快捷键不得吞掉退出路径。
- 焦点环使用 `#5F67FF`、2px；触屏按下反馈不能改变布局。
- 文字与背景优先使用高对比黑／纸组合；动态色必须经过前景色判断。

## 11. 新页面默认工作流

以后新增 Faces 页面，Design 和 Engineering 必须按此顺序执行：

1. 读取本规范、`faces-design-tokens.json` 和目标页面的当前实现。
2. 选择页面模板：Home 卡片、详情控制器、浏览／选择器、设置列表或原生交互例外。
3. 写一页简短 Brief，明确：真实目标、头部、电池、主要内容、底部控制、快捷键、状态、触摸区、动效、图层和冻结项。
4. 在施工前列出四层：产品语义、可见几何、触摸命中、素材来源；为每条外框、遮罩和装饰指定唯一归属，不能让热区或源素材偷偷生成新视觉边界。
5. 盘点素材是否为原始图层、透明素材或已烘焙成图；优先复用干净源素材。只有语义不同才新增组件或图标。
6. 在真实 320×240 页面和真实数据路由中实现；概念稿不能替代产品候选。
7. Design 在给 Alice 看之前，按第 12 节完成原生 1× 总览和至少 4× 边缘细查。
8. Alice 确认网页候选后，才能另行安排设备移植、构建、安装或 OTA；这些动作仍需各自授权。

若需求没有指定颜色，默认从页面语义选择现有 accent，而不是创造新色；若没有指定布局，默认使用标准详情页头部和图标控制区，而不是询问“要对齐哪个页面”。

## 12. Design 预审清单

提交 Owner Look 前逐项确认：

### 结构

- [ ] 真实画布为 320×240，所有可见内容在范围内。
- [ ] 返回、标题、状态和电池互不遮挡。
- [ ] 电池显示真实值或 `--`。
- [ ] 主要操作没有被装饰或文案替代。
- [ ] 底部紧凑控制使用图标 + 快捷键。
- [ ] 同级快捷键使用同一键帽视觉；同域入口没有被画成独立应用。

### 视觉

- [ ] 使用本规范纸色、墨色和语义强调色。
- [ ] 字体角色、字号和行盒符合标准；中文和 descender 未裁切。
- [ ] 封面为 3px 轻圆角、无黑描边，阴影连续。
- [ ] 页面只有一个主要彩色焦点。
- [ ] 旧原型数值没有覆盖当前 token。
- [ ] 每条外框只有一个明确拥有者；子元素、点击分区和烘焙素材没有重复画边。
- [ ] 圆形、圆角矩形、图标等对象保持真实轮廓；没有为修一个边缘而削平另一处轮廓。
- [ ] 已在原生 1× 检查整体层级和可读性，并在至少 4× 检查四边、四角、裁切、抗锯齿、遮挡和相切关系。

### 交互

- [ ] 触摸区与可见区分别核对，且不重叠。
- [ ] Keyboard3 快捷键、Q／Esc 和 S 路径保留。
- [ ] 加载、失败、空、陈旧、发送中和未知结果有明确状态。
- [ ] 动效中按钮禁用／恢复正确，reduced motion 可用。
- [ ] 装饰层始终在内容层后方；3D 场景无穿层。

### 交付边界

- [ ] 真实网页候选已操作，不用静态截图冒充交互。
- [ ] 网页通过、构建通过、生产同步、烧录和实机验收分别记录。
- [ ] 本轮决定、验证和未完成项已在维护者本地记录；对外变更已同步到相关公开文档。
- [ ] Owner Look 的对象和范围已写明；一个页面的“看着没问题”没有被外推成其他页面、状态或实机验收。
- [ ] 交接说明列出最终权威方案、冻结项、待确认项和明确作废的反例；“已发送 handoff”没有被写成“已实现”。

## 13. 精修、验收与交接纪律

Faces 的页面小、密度高，1–2px 足以改变对象关系。FACES-031～038 的迭代说明：设计精度不能只靠总体观感或测试通过，必须同时控制语义、几何、命中和素材。以下规则适用于所有新增页面与局部重构。

### 13.1 四层必须分开描述

| 层 | 回答的问题 | 禁止混淆 |
| --- | --- | --- |
| 产品语义 | 这是一个功能、同域入口，还是两个独立应用？ | 不用一条可见分割线替代信息架构判断。 |
| 可见几何 | 用户看见哪条边、哪个圆、哪块色面？ | 不让触摸热区自动变成视觉边界。 |
| 触摸命中 | 哪些像素可点、快捷键是什么、热区是否重叠？ | 不用可见按钮尺寸冒充完整触摸范围。 |
| 素材来源 | 元素来自原始图层、透明素材还是整卡成图？ | 不把烘焙进素材的旧边框当成对象本身。 |

Brief 至少要为主要对象写清这四层。修改其中一层时，默认冻结另外三层；需要连带调整时必须显式说明。

### 13.2 边界只有一个拥有者

- 页面、主卡、子组件和装饰色块都要指定边界拥有者。Music 主卡外框由主卡拥有；Collection 封套只拥有自己的局部轮廓；不可见热区不拥有边框。
- 子元素贴近父边时，要同时检查父边、子边、素材边和裁切边。两条线即使颜色相同，也不能因“看起来接近”而被视为一条。
- 为修复边缘问题，先找出多余边界的来源，再删除或隔离来源；不要先用覆盖条、额外描边或随意裁切把症状遮住。

### 13.3 素材复用必须尊重对象轮廓

- 优先使用无卡框、无背景、保留 alpha 的原始图层。复用整卡／整页成图前，先列出其中已经烘焙的边框、圆角、阴影和底色。
- 只能复用成图时，遮罩必须匹配对象语义：圆形对象用圆形遮罩，圆角封面用相同圆角，不能用矩形削边处理圆形对象。
- 布局框、可见轮廓和素材采样框是三个不同概念。修正素材采样不能静默改变对象直径、中心、宽高比或与相邻对象的间距。
- 放大检查必须覆盖完整轮廓，不能只看问题箭头指向的局部。FACES-037 的 2px 右裁消除了旧边框，却削平唱片，属于典型的局部修复破坏整体。

### 13.4 双尺度视觉验收

- **原生 1×／320×240**：检查信息层级、文字可读性、按钮识别、整体平衡和真实可视范围。
- **至少 4× 放大**：检查四边、四角、圆周、相切与留白、抗锯齿、源素材残边、遮挡顺序和 1px 漂移。
- 默认、按下、焦点、加载、禁用和动画中状态都要沿用同一边界与轮廓规则。静止画面正确不能替代状态检查。
- 自动化测试负责锁定结构和反例，但不能证明“看起来圆”“字形舒服”或“没有锯齿”；视觉预审和 Owner Look 仍是独立门槛。

### 13.5 验收范围必须精确

- Owner 的“好”“可以”“肉眼没问题”只确认当时展示的页面、状态和明确讨论对象。不得顺带推断另一个页面、图标、实机或尚未展示的状态已经通过。
- 同一页面后续发现具体问题，会重新打开对应局部验收；此前无关的已确认几何继续冻结，不重开整套设计。
- 网页候选通过、设备移植、构建、生产同步、烧录／OTA 和实机 Owner 验收继续分别记录。

### 13.6 失败方案也要进入交接

- 被否决的方案保留在维护者本地记录中，注明“已被哪一版替代、为什么失败”；这些内部过程记录不随仓库发布。
- 测试除确认“应该存在”外，还应对已知坏路径增加否定断言，例如禁止圆形唱片重新使用矩形 `inset` 裁边。
- Engineering handoff 必须包含：权威版本、有效几何、冻结项、待确认项、作废反例和交付边界。发出 brief 只表示完成交接，不表示目标 session 已实现或设备已更新。
